# Release `v1.0.0` (`2026-11-13`)

**reflbo-nm-epd-420 `v1.0.0`** is the first public release porting Dan Vybiral's [`Vybo/reflbo`](https://github.com/Vybo/reflbo) (`14593da`, `spec r56`) to the **RockBase NM-EPD-420 (BW)** ESP32-S3 e-paper + LoRa board.

---

## Highlights & Improvements
- **SSD1683 4.2″ E-Paper Driver (400×300, 1 bpp):** Native SPI driver behind the `st7305` abstraction supporting fast differential partial updates (`0x26` OLD / `0x24` NEW RAM synchronization), automatic full-refresh cycle every 20 partial updates to eliminate ghosting, ambient temperature compensation, and `BUSY` timeout tracking (`panel status`).
- **RockBase NM-EPD-420 Board Support Package:** Verified pin mapping from `board_pins.h`, shared I²C bus ESD leakage protection during deep sleep (`TEMP_CTL` / `CODEC_EN` rail isolation), ES8311 low-power standby initialization, and gated battery ADC divider measurement (`ADC_EN`).
- **SX1262 LoRa & MeshCore Companion Integration:** Complete SX1262 driver on `SPI3_HOST` with `LORA_EN` power gating, MeshCore flood/direct packet encoding, Ed25519 identity & AES-128 channel crypto, NimBLE Companion app bridge, on-device LoRa dashboard cards, and USB console CLI (`ver`, `lora ...`).
- **Power & Timing Accuracy:** `CONFIG_FREERTOS_HZ=1000` for sub-10 ms driver timing, Light Sleep Octal PSRAM retention (`CONFIG_PM_POWER_DOWN_CPU_IN_LIGHT_SLEEP=n`, `TAGMEM=n`), internal RC calibration (`CONFIG_RTC_CLK_CAL_CYCLES=3000`), and **Focus Super Power Mode** (`power focus`) for minimal quiescent wake power when LoRa is OFF.
- **AHT20 Climate Sensor:** Explicit `0xBE, 0x08, 0x00` calibration/init sequence with sleep transitions after sampling.
- **Release & Verification Automation:** Prefix-map scrubbing (`0` build-host path leaks), Docker `espressif/idf:release-v6.1` reproducible builds (`tools/build_release.ps1`), SHA-256 manifest, Windows PowerShell/Batch flashers (`--after watchdog-reset`, NVS/LittleFS safe), and GitHub Actions CI.

## Flashing (`COM` / USB-Serial-JTAG)

### Option A: Automated Windows Script (Recommended — preserves NVS & LittleFS config)
```powershell
.\release\flash.ps1 -Port COM15
```
Or double-click `release\flash.bat` and enter your COM port (`COM15`).

### Option B: Unified Full 16 MB Image (`0x0`, fresh / factory flash)
```sh
python -m esptool --chip esp32s3 --port COM15 --baud 921600 \
  --before default-reset --after watchdog-reset write_flash \
  --flash_mode dio --flash_size 16MB --flash_freq 80m \
  0x0 reflbo-nm-epd-420-full-16MB-v1.0.0.bin
```

### Option C: Web UI OTA Update (existing `reflbo` installation)
Upload `reflbo-nm-epd-420-v1.0.0.bin` via the Web Configurator **Firmware** page (`http://192.168.4.1` or `reflbo-XXXX.local`).

> **Note for ESP32-S3 USB-Serial-JTAG:** When leaving ROM download mode (`BOOT` held on reset), use `--after watchdog-reset` (esptool >= v4.7 / v5.x) or power-cycle the board with `PWR` so the ESP32-S3 re-samples strapping pins and boots the application.

## Package Contents & Integrity
Checksums for every binary and flash helper are published in `SHA256SUMS.txt`:
- `reflbo-nm-epd-420-full-16MB-v1.0.0.bin` — Unified factory flash image starting at `0x0` (`bootloader.bin` + `partition-table.bin` + `ota_data_initial.bin` + `reflbo-nm-epd-420-v1.0.0.bin`).
- `reflbo-nm-epd-420-v1.0.0.bin` — Application binary (`ota_0` @ `0x20000` / Web UI OTA).
- `bootloader.bin`, `partition-table.bin`, `ota_data_initial.bin` — Individual boot/partition components for modular reflashing without overwriting NVS (`0x9000`) or LittleFS (`0x830000`).
- `flash.ps1`, `flash.bat` — Windows flash scripts with UTF-8 encoding & `watchdog-reset` handling.
- `SHA256SUMS.txt` — SHA-256 verification sums.
